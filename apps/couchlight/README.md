# Couchlight, live demo

What runs here:

- `index.html`: a mock TV game library. Only **Play** works (mouse, Enter, or A on a controller); everything else is inert scenery and the page says so. It borrows the idea of a console library, not anyone's logo or name.
- `app/`: **Couchlight's real renderer**, the `src/` of `Documents/Code/SteamStreamer`, unchanged, built for the web. The grid, the settings, the controller guide and real gamepad support (via the browser's own Gamepad API) all run.
- `electron-stub.js`: the only code here that is not Couchlight's own. It is a clearly labelled browser stand-in for `window.electronAPI` (the Electron preload bridge). It answers the five calls the interface makes and shows the twelve services in the state the 0.9 beta ships in: the DRM services greyed "Pending".
- Picking a service opens a card explaining what the desktop app would do (open the service inside its own window, controller still driving it). A web page cannot host those sites that way. Nothing fakes a stream.

Electron is never started, not to build and not to test.

## Rebuild after Couchlight changes

From `Documents/Code/SteamStreamer`:

```
COUCHLIGHT_WEB_OUT="<path to>/RosePortfolio-v2/apps/couchlight/app" npx vite build --config backups/vite.web-demo.config.mjs
```

That config lives in the Couchlight repo's gitignored `backups/` folder, so the Couchlight repo is unchanged. The build empties `app/`, so afterwards re-add this line to `app/index.html`, before the module script:

```
<script src="../electron-stub.js"></script>
```

If Couchlight's list of services changes, update `electron-stub.js`: it copies the list from `electron/main.js` rather than reading it.

`app-art/` holds Couchlight's own Steam library images, generated by its `build-steam-art.cjs`. The background has been downsized from 3840 px to 1920 px.
